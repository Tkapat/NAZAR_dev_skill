RULES FOR THE AI BUILDER (read first, obey exactly)
------------------------------------------------------------------
 1. Python 3.10 or 3.11. FastAPI + Uvicorn. Sync endpoints (def) are
    fine; run heavy vision work in a thread pool, never inside an async
    def body (use starlette.concurrency.run_in_threadpool). File upload
    endpoints may be async.
 2. There is NO Supabase. Database = MongoDB Atlas via PyMongo (sync),
    ONE cluster, ONE database "devskill". MONGODB_URI, JWT_SECRET,
    FERNET_KEY, FILE_URL_SECRET live only in backend .env and are never
    returned or logged.
 3. Frontends only call this API. Every endpoint uses
    Depends(require(...roles...)) except the PUBLIC ones listed.
 4. Centre-side roles may only touch documents whose centre_id equals
    user["centre_id"]. Call assert_centre_access() or filter by
    centre_id in EVERY centre route. Never trust a centre_id sent by
    the client; take it from the token's user.
 5. All timestamps = timezone-aware UTC datetimes. Date-only values are
    "YYYY-MM-DD" strings (calendar dates are IST dates), time-of-day
    values are "HH:MM" strings.
 6. Raw frames are NEVER written to disk or database, never logged, never
    returned. Only blurred, annotated, resized JPEG thumbnails (<=60 KB)
    may be saved. Frames pushed by the browser are decoded in memory,
    processed and dropped. The camera reference frame is blurred with
    the same privacy function before storage.
 7. Never store plain passwords. Temporary passwords are returned once.
 8. Errors: {"detail": {"detail": "...", "code": "SOME_CODE"}} via
    HTTPException(status, detail={...}). 401, 403, 404, 409, 422, 429.
 9. Do not invent collections or fields. Use only the shapes in the
    COLLECTIONS section. Ask before changing a shape.
10. Every state-changing officer/admin action writes to audit_log
    (insert-only). Live snapshots are NOT audit-logged (volume) but are
    covered by ledger batch digests (see INTEGRITY).
11. Thresholds live in trade_templates / camera.live, not in code.
12. IDs: store ObjectId internally; return strings under key "id".
    Parse incoming ids with oid() (422 BAD_ID).
13. Lists: ?limit=25 (max 100) and ?cursor=<last id>. Never skip().
    Return {"items":[...],"next_cursor":..}.
14. No DB triggers: invariants are enforced in code.
15. Public routes are rate limited (slowapi 20/min/IP; login 10/min).
    The frame endpoint is NOT subject to the default limiter; it has its
    own per-camera minimum spacing (0.5 x interval, 429 TOO_FAST).
16. Do not add features not listed.
17. LIVE PATH MUST BE FAST: target <= 1.5 s per frame on a 2-vCPU CPU
    (yolo11n, tiling OFF by default for live frames). Cap concurrent
    inference with a semaphore (2). If busy return {"accepted":false,
    "reason":"BUSY"} (HTTP 200), never queue.
18. SERVER TIME ONLY: snapshot timestamps are server time, never client
    time. Calendar dates are computed in Asia/Kolkata.
19. WRITE FALLBACK: if Atlas is unreachable (exception/timeout 3 s), a
    snapshot or observation is appended to the local ledger (kind
    "snapshot"/"observation") and replayed by sync_tick. live_status is
    best-effort (skipped when offline).
20. Provisional cameras (setup_status != approved) update live_status
    only. They never write snapshots, timelines, summaries or flags.

LIVE MONITORING AND CALENDAR (core of v3)
------------------------------------------------------------------
 A. CAMERA SOURCE KINDS  (cameras.source_kind, derived from source_uri)
    browser        source_uri "browser". A browser tab (Centre portal
                   /live) captures frames and POSTs them. Works with the
                   backend anywhere (laptop, Azure VM).
    webcam         source_uri "webcam:0". Backend reads the machine's
                   own webcam with cv2.VideoCapture(index) (on Windows
                   use cv2.CAP_DSHOW). Only works when the backend runs
                   on that PC.
    rtsp           rtsp://... read by the backend.
    file           "file:<name>" from sample_videos/ (Demo Lab only,
                   never in live_capture_tick).
    Per-camera live settings: cameras.live = {enabled, interval_s (5..120),
    tiling(bool, default false)}; cameras.subtract_staff(bool, default true
    for the first camera of a centre); cameras.zone_label (text).
    MULTIPLE CAMERAS: each camera must cover a different area. Session
    observed count = SUM over cameras (ci_low/ci_high summed).

 B. FRAME FLOW (process_live_frame; see KEY CODE)
    1 Resolve camera, centre, template, ACTIVE session (now between
      start_ts and end_ts) or None.
    2 Quality gate (dark/covered/blurry/frozen). Bad frame: live_status
      state "tampered", camera_health event (only on state change), after
      3 consecutive bad frames inside a session raise C1 (deduped).
      Bad frames are never counted.
    3 Detect (full frame; tiling only if camera.live.tiling) -> cleanup
      (ROI, presence rule, staff subtraction) -> item_usage().
    4 Per-snapshot output:
        people            counted people (after rule + staff subtraction)
        people_raw        people boxes inside ROI before the rule
        items {class: {present, in_use, idle, off}}
        people_smooth     median of the last 5 snapshots (what UIs show big)
    5 Thumbnail: heads blurred, boxes + labels drawn, 640 px, JPEG q60.
      Saved as evidence_blobs _id "live_<camera_id>" (replace, expire 1 day)
      every frame; plus ONE routine thumbnail every ROUTINE_EVIDENCE_EVERY_MIN
      minutes (kind "routine", expire 14 days).
    6 live_status upserted (always). If camera approved AND session active:
      insert snapshots doc, update day_timelines (max one point per
      LIVE_TIMELINE_GAP_S), daily_summaries ($inc/$max/$min), sessions
      done_captures. Every CONSOLIDATE_EVERY_SNAPSHOTS recordable snapshots
      (and at session close) run consolidate_session().
    7 Response to the browser: {accepted, state, session, people,
      people_smooth, items, boxes[{cls,x1,y1,x2,y2,conf}] normalised 0..1
      (for drawing on the LOCAL preview), next_interval_s}.

 C. IN-USE DEFINITION (usage.py; per item, per snapshot)
    present   detected inside the camera ROI.
    in_use    a person box (expanded 15 %) overlaps the item box; for
              operability "screen_on" classes (monitor/laptop/tv) the
              screen must ALSO be on (brightness > 70 or std > 35).
    off       screen class, screen not on.
    idle      present, not off, nobody near.
    operability "none" = count presence only (no usage states).
    Session usage % per class = mean(in_use) / mean(present) over snapshots.

 D. CONSOLIDATION AND FLAGS (rolling)
    consolidate_session(session_id, camera, final):
      counts = last max_frames snapshots' people; consolidate() with the
      template tolerance/agree_ratio; equipment per class from present
      counts (min_frames 3) plus in_use_pct. Upsert observations
      {source:"live"} keyed (session_id, camera_id, hour_bucket); ledger
      entry only when observed/ci/state changed.
      Flag evaluation (flag_engine.evaluate) runs only when frames_used
      >= base_frames. U1 and C3 are raised only when final=True (session
      closed). Flags are upserted by dedupe_key
      "<session_id>:<type>[:<class>]": existing open flag -> update
      reason/details; new -> insert + ledger("flag") + recompute_risk.
      Claim may arrive after capture started: evaluation simply uses the
      claim when it exists.
      sessions.summary = {claimed, observed, ci_low, ci_high, state, delta,
      snapshots, staff_verified} is rewritten after each consolidation.

 E. CALENDAR DATA MODEL (calendar.py)
    Per snapshot we update, in this order: snapshots (14 d TTL),
    day_timelines (downsampled points, kept), daily_summaries (kept).
    "updates" for a day = snapshots + claims + flags + camera health
    events + session open/close events.
    Day status (computed at read time, no extra storage):
      holiday   date in holidays
      upcoming  date > today (and sessions scheduled)
      none      no sessions and no data
      no_data   sessions scheduled but no snapshots
      critical  any flag high/critical that day
      attention any open flag that day
      ok        data present, no open flags
    Range endpoint merges THREE grouped queries (daily_summaries, sessions
    grouped by date, flags grouped by IST date). No per-day queries.

 F. STALENESS
    live_status.ts older than 3 x interval -> API reports state "offline".
    No active session and fresh frames -> state "idle". Provisional
    camera -> state "provisional". Healthy + session -> "live".

 G. SERVER-SIDE CAPTURE (live_capture_tick, webcam/rtsp only)
    For each camera with live.enabled, kind webcam|rtsp, a centre that is
    live/pending_setup and an ACTIVE session: if now - last_snapshot >=
    interval -> read one frame from a cached cv2.VideoCapture (opened
    lazily, released after 60 s idle or on error, retried every 30 s) and
    call process_live_frame(). Cameras are enabled/disabled via
    PUT /my/cameras/{id}/live.

VISION PIPELINE SPEC
------------------------------------------------------------------
 detector: canonical names. COCO_TO_CANON = {"tv":"monitor","dining table":
   "desk"}. If template.detector_backend=="coco" or (auto and every class in
   COCO_OK) -> YOLO("yolo11n.pt") with the alias map; else YOLOWorld(
   "yolov8s-worldv2.pt") with set_classes(template.detector_classes).
   Cache models per (class set, tiling). Load once at first use (warm up
   at startup with one dummy frame to avoid a slow first request).
   COCO_OK = {person, chair, desk, monitor, laptop, keyboard, mouse,
   "cell phone", bench, couch, book, bottle}. "desk" through COCO
   "dining table" is a proxy; if eval shows weakness use YOLO-World.
 Tiling: full frame + 2x2 overlapping tiles for Demo Lab/eval and for
   cameras with live.tiling=true. Live default OFF.
 Quality gate: dark(mean<25), covered(std<12), blurry(laplacian<40),
   frozen(diff<0.5 with gap>=20 s), moved(phase shift>5 % vs reference,
   only when a reference gray frame is cached).
 Replay (C2): dhash per accepted frame every 60 s into frame_fingerprints;
   hamming <=3 vs a different session/day on the same camera -> C2.
 Cleanup: ROI by reference point; presence rule per template; subtract
   verified staff (once per session total: only cameras with
   subtract_staff=true subtract); if no staff verified subtract 1 and
   S1 (raised once per session).
 Usage: usage.item_usage() (section C).
 Privacy/thumbnail: blur top 28 % of every person box; draw boxes with
   labels for all classes; 640 px; JPEG q60 (<=60 KB); drop raw frame.
 Demo scenarios (sample videos) still run through pipeline.analyse_hour().

FLAG TYPES (flag_engine.evaluate; unchanged semantics)
------------------------------------------------------------------
 A1 A2 A3 A4 A5 E1 E2 E3 S1 C1 C2 C3 D1 U1 P1 as in v2.
 margin = max(count_tolerance, ceil(0.10 * claimed)).
 Severity by gap ratio (<15 low, <30 medium, <50 high, else critical),
 +1 level if the same type repeats >=3 times in 7 days.
 Live additions: all flags are upserted by dedupe_key; E2 uses the
 snapshot "off" state (screen classes) over >=60 % of snapshots; E1 uses
 present counts; "in use" alone never creates a flag (usage is reporting).
 After any flag change: recompute_risk(centre_id) and update
 daily_summaries.updated_at.

INTEGRITY AND SYNC
------------------------------------------------------------------
 - Claims, observations, flags -> ledger (SHA-256 chain + Ed25519)
   BEFORE sync, as in v2.
 - Snapshots are NOT ledgered one by one. Every consolidation appends a
   ledger entry kind "snapshot_batch" {camera_id, session_id, from_ts,
   to_ts, n, digest = sha256 of "ts|people|items-json" lines}. Central
   verification can recompute the digest from snapshots still inside the
   TTL window.
 - Offline writes: store(doc) tries Mongo (3 s timeout); on failure appends
   ledger kind "snapshot" with the doc; sync_tick replays idempotently via
   snap_key and re-applies timeline/summary updates only when the snapshot
   was newly inserted.
 - Offline toggle (Demo Lab) sets sync STATE; live_status is skipped.
 - D1 flag on chain verification failure (as v2).

PRIVACY AND SECURITY CHECKLIST
------------------------------------------------------------------
 - Trainees: no face/photo anywhere. Staff: consent flag, encrypted
   embedding, own-record verification only (as v2).
 - Browser agent: JPEG frames are sent over HTTPS to the edge backend,
   decoded in memory, processed, dropped. No frame is ever written or
   logged. Local preview exists only in the user's browser.

 # FILE: app/services/vision/usage.py   (replaces equipment.py)
 import cv2
 SCREEN = {"monitor", "laptop", "tv"}
 def _near(item, p, pad=0.15):
     pw, ph = p[2] - p[0], p[3] - p[1]
     x1, y1, x2, y2 = p[0] - pad * pw, p[1] - pad * ph, p[2] + pad * pw, p[3] + pad * ph
     return min(x2, item[2]) > max(x1, item[0]) and min(y2, item[3]) > max(y1, item[1])
 def screen_on(frame, box) -> bool:
     x1, y1, x2, y2 = [max(0, int(v)) for v in box[:4]]
     r = frame[y1:y2, x1:x2]
     if r.size == 0: return False
     g = cv2.cvtColor(r, cv2.COLOR_BGR2GRAY)
     return bool(g.mean() > 70 or g.std() > 35)
 def item_usage(frame, items, people, rules: dict) -> dict:
     """items: non-person dets (x1,y1,x2,y2,conf,name) inside ROI; people: ALL person boxes in ROI;
        rules: {class: operability}. -> {class:{present,in_use,idle,off}}"""
     out = {}
     for it in items:
         c = it[5]; s = out.setdefault(c, {"present": 0, "in_use": 0, "idle": 0, "off": 0})
         s["present"] += 1
         mode = rules.get(c, "none")
         if mode == "none": continue
         if mode == "screen_on" and c in SCREEN and not screen_on(frame, it): s["off"] += 1
         elif any(_near(it, p) for p in people): s["in_use"] += 1
         else: s["idle"] += 1
     return out

         eq[cls] = {**consolidate(pres, tpl["count_tolerance"], float(tpl["agree_ratio"]), min_frames=3), "in_use_pct": round(100 * use / tot)}
